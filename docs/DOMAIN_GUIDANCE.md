# 行业领域指导上下文

## 目标

领域指导上下文用于让简历审阅、改写和模拟面试理解岗位的真实业务链路，而不是把通用建议机械替换成行业术语。当前版本为 `2026.07.29`，覆盖运营与产品运营、云商务与 GTM、游戏运营发行、全球传播、游戏音频商务拓展五类岗位。

这层上下文只是一份审阅量表，不是候选人事实来源。任何工具、指标、方法、职责、权限或成果仍须来自简历原文、证据声明或用户明确确认的事实；不能因为知识库提到了某个术语，就把它写进候选人的经历。

## 运行方式

服务器在最小化、脱敏后的 provider DTO 上做确定性词项匹配。只有达到阈值时才选择一个得分最高的领域，具体岗位包优先于通用运营包；未命中时沿用原提示词，不注入领域内容。

领域上下文目前用于 `resume.score`、`resume.suggest`、`resume.chat`、中英文证据改写、`interview.plan`、`answer.evaluate` 和 `answer.coach`。`jd.parse` 仍只抽取 JD 的原文要求，`job.match` 仍只依据服务端允许引用的声明做映射，避免领域词典改变事实判断。

简历能力只能使用证据中已经存在的行业词，否则应提出精确追问或省略。面试能力可以用领域概念设计场景和评分观察点，但不能暗示候选人做过该事项，也不能把单一术语或方法论当作唯一正确答案。

本版从用户提供的六份专家资料中提炼共同原则、岗位信号、业务链路、指标边界和面试追问维度：

- `行业黑话语料_游戏运营发行(1).json`
- `运营岗简历经历行业化改写指南(1).md`
- `Global_Communications_Resume_Guide(1).json`

原始资料未整包提交到仓库。运行时只保留经过压缩、去除个人贡献者信息和示例占位数字后的指导原则，避免扩大提示词体积，也避免模型把示例误当成候选人事实。资料按内部参考内容管理；对外分发或商用授权需由项目维护者另行确认。

## 五类指导重点

| 领域 | 审阅重点 | 典型追问 |
| --- | --- | --- |
| 运营与产品运营 | 细分方向、业务问题、用户对象、动作方法、指标口径、复盘与 SOP | 指标基线、分层逻辑、实验设计、优先级、失败复盘 |
| 云商务与 GTM | 线索到商机的阶段、资质筛选、客户痛点、价值主张、伙伴与 CRM 纪律 | 线索质量、BANT 或实际筛选方法、异议、POC 交接、赢单或丢单复盘 |
| 游戏运营发行 | 版本节奏、用户与活动机制、渠道适配、内容表现、反馈闭环 | 运营假设、目标人群、机制选择、依赖方、数据解释、下一轮迭代 |
| 全球传播 | 英文交付物、编辑判断、事实核验、跨市场适配、审核与发布结果 | 编辑取舍、术语一致性、文化语境、审核冲突、传播效果衡量 |
| 游戏音频商务拓展 | 业务类型、客户与需求场景、方案报价、版权边界、制作交付与回款 | 需求转译、授权范围、资源与排期、反馈交接、验收风险、个人权限 |

## 维护规则

新增资料时先判断是通用原则、现有领域补充还是新领域。只有能够改变审阅判断或追问质量的内容才进入运行时；长篇示例、人物信息、公司专属数字和同义术语表留在离线资料中。

修改 [`domain-guidance.ts`](../src/lib/server/ai/domain-guidance.ts) 时同步更新版本、选择测试和 provider 集成测试。匹配规则必须有未命中测试与相近领域优先级测试，避免普通技术简历因“云原生”等弱信号误用云商务指导。
