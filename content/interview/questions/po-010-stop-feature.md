# 停止一个功能 / Stopping a feature

## 问题 / Question

**中文：** 一个功能有少量忠实用户，但维护成本持续上升且不支持战略方向。你如何决定是否下线并减少伤害？

**English:** A feature has a small loyal user base, but maintenance cost is rising and it no longer fits strategy. How would you decide whether to retire it and reduce harm?

## 追问 / Follow-ups

- 中文：哪些用户行为比总体使用率更重要？ / English: Which user behaviors matter more than aggregate usage?
- 中文：迁移完成的标准是什么？ / English: What defines a completed migration?

## 优秀信号 / Strong signals

- 评估用户关键性、替代方案、成本、风险和战略机会成本。 / Assesses user criticality, alternatives, cost, risk, and strategic opportunity cost.
- 提前通知、提供导出/迁移和高风险用户支持。 / Provides notice, export or migration, and support for high-risk users.
- 设置退场指标并监控意外影响。 / Defines retirement metrics and monitors unintended impact.

## 评分锚点 / Scoring anchors

- `1`：只按用户数量立即关闭。 / Shuts down immediately based only on user count.
- `3`：有成本分析和通知迁移，但关键用户识别有限。 / Has cost analysis and migration notice with limited critical-user analysis.
- `5`：透明权衡、分层迁移、保护数据可携带性并验证替代路径。 / Balances transparently, migrates by segment, protects portability, and validates alternatives.

## 风险项 / Risks

- 将沉没成本作为继续投入的唯一理由。 / Uses sunk cost as the sole reason to continue.
- 在迁移前删除用户数据或工作流。 / Removes user data or workflows before migration.
